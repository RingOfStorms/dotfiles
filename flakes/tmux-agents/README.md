# tmux-agents

Agent awareness for a plain tmux setup, with no plugins inside the harnesses. Supports omp, opencode and Claude Code.

- **Navigator** (`prefix + w`, or tap the session badge / agent counts in the status bar): a tree of Git project (blue, with its main checkout path) > session (purple, with its `@session_ai_name` label if set, `[branch]`, and pane count) > agent panes and agent-less windows, in window-index order. Pane names follow the pane border: the pane option `@pane_name` if set, else the running command. An agent row shows its agent label, its `@pane_name` as `[name]` if set, and `(window index:name · other panes)` listing the window's non-agent panes. A window without agents gets its own row, `index:name` plus the names of all its panes, unless it is the only window of a session without agents (that session row stays the leaf). Every pane name is part of the search text, so typing a pane name finds its row. Sessions spanning repos belong to the repo containing the most panes; ties use the first pane in tmux list order. Non-Git sessions are top-level purple rows with their active pane's path. Project and session rows open the session's active pane on Enter/click, window rows the window's active pane; agent rows open their own pane. The cursor starts on the current pane's agent row, else its window row, else its session row. Matching is exact (fzf `--exact`): each space-separated term must appear as a substring, so `reduc` no longer matches scattered letters; prefix a term with `'` for fuzzy. Grouping is recomputed every refresh; the list refreshes every second only when rows change, retaining the selected stable ID. Ctrl-J/K wraps; Ctrl-D/U pages down/up. Ctrl-X confirms `[y/N]` before killing the selected session, window or pane (project rows can't be killed). Live previews move below the list on narrow terminals.
  Keys: the navigator opens in nav mode with the query input hidden, where plain keys act: `j`/`k` move, `c` create, `x` kill, Enter switch. Every leaf row (an agent pane, a window row, or a session with neither) shows a yellow jump label in the left column, `1`-`9` then `Q`-`P` in display order; pressing that key (lowercase) switches straight to the row's pane. Rows past the 19th get no label. `/` enters search mode: the input appears, the labels disappear, and plain keys type into the query, while `ctrl-j/k/d/u/c/x` keep working (they also work in nav mode). Esc closes the navigator in either mode.
  Ctrl-C opens a session-name prompt: Enter creates, Esc cancels. The navigator reopens after either action; select the new session to switch to it. New sessions start in the selected pane's directory (the current pane's directory when the filter has no matches). Blank names create nothing; tmux rejects duplicates/invalid names without closing the navigator.
- **State**: a status-line `#()` tick (every `status-interval`, at most 2s) reads `#{pane_title}` and `#{pane_current_command}` for all panes (plus the screen of opencode panes) and sets `@agent_state` (`working|idle|input`) per pane, `@agent_unseen` when an agent finishes or asks for input while you aren't looking at it, and `@agent_win` (`input|done`) per window. Unseen clears when you view the pane (selection hooks re-run the tick immediately). `@agent_watch_until` (epoch seconds) marks a pane as watched somewhere else: tmux-agents-mobile sets it while a phone has the pane open, and the tick then treats that pane as seen, so desktop notifications and sounds stay quiet for as long as the phone is watching.
- **Status**: segment prepended to `status-right` (`! n` needs input, `⠿ n` working, `● n` done unseen); non-current windows get a `!`/`●` marker in front of catppuccin's format.
- **Notifications** (when an agent finishes or needs input while you aren't looking): one master switch plus independent channels. `desktop` = notify-send on the tmux host; `message` = tmux message on every attached client (reaches ssh/mobile); `sound` = `off` | `local` (pw-play/paplay a file on the tmux host; separate done/needs-input sounds) | `bell` (terminal bell to each attached client, so an ssh/mobile client beeps or vibrates). Events in one tick are batched: one sound and one message.
- **Resume** (`resume.sh`, toggle with `resume.enable`): `$XDG_STATE_HOME/tmux-agents/resume.tsv` maps each agent pane to its session. The tick saves agent changes and retries unresolved running agents; every tmux-resurrect save also updates the map. After resurrect restores the layout, each mapped pane gets `omp --resume=<file>` or `opencode -s <id>`: run (`auto`) or only typed (`prompt`), once the configured default shell replaces any pane-contents replay wrapper. Existing running agents are left alone. See [Resume state and recovery](#resume-state-and-recovery).

## Resume state and recovery

Each `resume.tsv` row is `session<TAB>window<TAB>pane<TAB>agent<TAB>ref<TAB>state`. `ref` is an omp session file, or an opencode or Claude Code session ID. Older 4-column rows imply omp; older rows without a state imply `live`.

- `live`: an agent was running at the last save. For an existing mapping, process detection—not the pane title—determines whether it is still running.
- `pending`: restore was attempted, but a subsequent save has not successfully resolved the running agent's session. Failed launches, shell-readiness timeouts, failed opencode database lookups, and commands waiting for Enter remain retryable rather than disappearing on the next save.
- `gone:<epoch>`: a previously running agent was no longer detected. Its mapping is retained for 60 seconds, then removed by a later save. This protects the short interval between agents exiting and tmux stopping during shutdown. An intentional quit followed by a restart before that later save can resume the agent again.

Failed or empty pane listings leave the map untouched. The pre-restore hook freezes saves while resurrect creates panes; restore holds the map lock until all resume workers finish, including manual restores. A save removes mappings whose pane addresses no longer exist and replaces mappings when another agent session is resolved. Restore removes references to sessions that no longer exist (`opencode -s` with an unknown ID would start a new session). An opencode reference is removed only after a successful lookup finds no session; query errors, including SQLite busy timeouts, skip launch, retain the mapping as `pending`, and record the lookup failure in `restore.log`.

To retry a failed restore, run `tmux-agents restore` (`bin/tmux-agents restore` in the installed plugin directory). It waits up to about 15 seconds per pane for the configured default shell; it does not verify that a sent command successfully launched the agent. `$XDG_STATE_HOME/tmux-agents/restore.log` records each restore's sends, skips, and failures and is replaced by the next restore. A pending row remains until a session resolves, its reference disappears, or its pane address is removed; it can therefore be retried on later restarts too.

Resurrect must have saved the pane layout: the map alone cannot recreate panes added since its last save. Mappings use session/window/pane indices, so reusing those addresses before a save can retain an old mapping. Without resurrect, the file still identifies the sessions each pane was running.

## Detection

An agent pane is recognized by its terminal title; no harness plugin is needed, and sandbox wrappers like `nono run ... -- omp` work unchanged.

- **omp** titles itself `π <spinner> label` while working, `π > label` when idle and `π ! label` when blocked on an ask/approval prompt. State comes from the title alone.
- **opencode** titles itself `OpenCode` (home screen or untitled session) or `OC | <session title>`, regardless of state. resurrect can restore that title onto a fresh shell, so the pane only counts while `#{pane_current_command}` is `opencode` or `nono`. State comes from the last 4 non-blank rows of `capture-pane`: permission buttons or a question footer inside the `┃` dialog = `input`, the `■⬝` spinner footer as the last row = `working`, anything else = `idle` (an interrupted turn reads as idle). Only gated panes are captured.
- **claude** (Claude Code) titles itself `✳ <topic>` when idle and `⠂`/`⠐ <topic>` while working. A pane counts while `#{pane_current_command}` is `claude` (or the nix `.claude-wrapped`), or `nono` with such a title. A `Do you want to …` permission prompt or an `Esc to cancel` dialog footer in the last 12 non-blank rows = `input`; otherwise the spinner title = `working`, else `idle`.

Other titles aren't agents. To add another harness, extend `agent_kind`, `classify` and `agent_label` in `tmux-agents.sh`, and `session_for_pane` in `resume.sh`.

For resume, the agent is found by walking the pane's process tree (the shallowest `omp`/`opencode`/`claude` process; wrappers run it as a child).

- **omp**: the session file is the JSONL the `omp` process holds open, falling back to omp's per-terminal breadcrumb (`~/.omp/agent/terminal-sessions/pts-N`) for the agent's own tty. The pane tty's breadcrumb is not used: wrappers can give omp a separate pty, leaving an unrelated session at the pane tty.
- **opencode**: the session ID comes from the process's `-s`/`--session` argument (as resumed panes have) when the title still matches it; otherwise a read-only lookup in opencode's SQLite DB (`session_v2`, `$OPENCODE_DB` or `$XDG_DATA_HOME/opencode/opencode.db`) picks the newest root session whose directory is the agent's cwd (or an ancestor) and whose title matches the pane title (the 37-char `…` truncation included). A bare `OpenCode` title is unresolvable until the session gets a title; the tick retries.
- **claude**: the session ID is `sessionId` in Claude Code's per-process file `${CLAUDE_CONFIG_DIR:-~/.claude}/sessions/<pid>.json`, which follows `/resume` and `/clear`. Restore drops rows whose `projects/*/<id>.jsonl` transcript is gone, and resumes with `claude --resume <id>`.

Resume is typed into the interactive shell, so your `omp`/`opencode`/`claude` aliases (and their wrappers) relaunch the session.

## Options

Home Manager: import `homeManagerModules.defaultEnabled` (on by default) or `homeManagerModules.default` (set `enable` yourself). Options: `ringofstorms.tmuxAgents.{enable,key}`, `ringofstorms.tmuxAgents.resume.{enable,mode,ompCommand,opencodeCommand,claudeCommand}` and `ringofstorms.tmuxAgents.notifications.{enable,desktop,message,sound,soundDone,soundInput,doneVolume,inputVolume}`. Resume hooks are registered at the beginning of tmux.conf, before continuum can start an automatic restore. The status/theme loader remains after catppuccin/resurrect/continuum via `lib.mkAfter`. For a manual installation, run `bin/tmux-agents resume-init` before loading continuum, then load `tmux_agents.tmux` after the theme.

tmux options: `@tmux-agents-key` (`w`), `@tmux-agents-mouse` (`on`: status-left and agent-count taps open the navigator, replacing the default status-left click), `@tmux-agents-notify` (`on`, master), `@tmux-agents-notify-desktop` (`on`), `@tmux-agents-notify-message` (`off`), `@tmux-agents-notify-sound` (`local`; `off|local|bell`), `@tmux-agents-sound-done` / `@tmux-agents-sound-input` (file paths), `@tmux-agents-sound-done-volume` / `@tmux-agents-sound-input-volume` (`15` / `90`, percent), `@tmux-agents-resume` (`on`), `@tmux-agents-resume-mode` (`auto`; `auto|prompt`), `@tmux-agents-resume-command` (`omp --resume=`), `@tmux-agents-resume-command-opencode` (`opencode -s `), `@tmux-agents-resume-command-claude` (`claude --resume `), `@tmux-agents-interval` (`2`), `@tmux-agents-navigator-interval` (`1`), `@tmux-agents-popup-width`/`-height` (`85%`/`75%`). All are read at event time, so `tmux set -g @tmux-agents-notify off` takes effect immediately.

CLI (`bin/tmux-agents` in the plugin dir): `tick [quiet]`, `navigator`, `rows [--json]`, `preview TARGET`, `kill ID ROWS`, `create TARGET ROWS`, `save`, `restore`, `restore-begin` (pre-restore write freeze), `resume-init` (adds or removes the resurrect hooks per `@tmux-agents-resume`). `rows --json` (used by tmux-agents-mobile) emits the navigator tree as objects of `kind` `repo`, `session`, `pane` (agent; with `pane_name` and `others`, the window's non-agent pane names) and `window` (`id` `w:SESSION:INDEX`, `label` = all its pane names, `panes` = pane count). `kill` takes `s:`, `w:` and `p:` IDs.

## Tests

Run `bash flakes/tmux-agents/tests/resume.sh` and `bash flakes/tmux-agents/tests/claude.sh` (Claude Code detection, screen states, PID-file sessions, save/restore with stubbed tmux) from the repository root (Bash, coreutils, util-linux, and sqlite3 required). These isolated state-transition regressions cover failed/empty listings, pending and unresolved launches, session replacement, stopped-agent grace expiry, closed pane addresses, and failed versus successfully empty SQLite lookups without connecting to your tmux server.
